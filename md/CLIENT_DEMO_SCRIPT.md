# Private Client Demo Script

Use this 5–10 minute walkthrough only in the protected demo with fictional
records. It demonstrates workflow and safety controls, not real product,
price, delivery, payment, policy, or WhatsApp commitments.

## Before the call

For the connected product/gallery walkthrough, follow
[Dashboard to storefront workflow](../storefront/PRODUCT_WORKFLOW.md).
Demonstrate a saved dashboard edit appearing after storefront reload using
fictional records and photos in the real backend. Do not use the historical
mock catalogue server for this walkthrough.

- Open `https://demo.bahuluberrycameron.com` and sign in as the demo Owner.
- Confirm the demo data is fictional and that no live WhatsApp sending is
  enabled.
- Start from the Dashboard and keep this script open in a separate tab.

## 1. Dashboard overview — 1 minute

1. Show the collapsible navigation and Dashboard summary cards.
2. Explain that staff work from one internal workspace for orders, inventory,
   tasks, support handoffs, and operational help.
3. Mention that all shown records are fictional demo data.

## 2. Daily operations — 2 minutes

1. Open **Orders** and show filtering/status visibility on a fictional order.
2. Open **Inventory** and show product stock visibility and the adjustment
   workflow (do not make a real-business claim from demo values).
3. Open **Tasks** and show how the team can see or update internal work.

## 3. Operations Copilot — 2 minutes

1. Open **Operations Copilot** and select a suggested read-only prompt such
   as the shift handover or low-stock review.
2. Explain that Staff receive live read-only help; the answer is based on
   dashboard data, not invented numbers.
3. As Owner, ask for a safe action preview, for example creating a fictional
   task.
4. Point out the preview card: it shows what will change, but has not changed
   anything yet.
5. Click **Cancel** once, then repeat and click **Confirm**. Show the
   resulting refresh/activity. Explain that confirmation is one-time and
   server-authorised.

## 4. WhatsApp semantic support preparation — 3 minutes

1. Open the **WhatsApp** workspace and its Knowledge Articles/approved content
   area. Show that English and Bahasa Melayu source text is Owner-approved.
2. In the simulator, send the fictional English message:
   `Is this a fictional demo answer?`
3. Show the concise draft and its source citation. Explain: it searches only
   same-language, approved content and produces a draft for staff review; it
   does not send a WhatsApp message.
4. Send the fictional Bahasa Melayu message:
   `Boleh saya tahu sama ada ini jawapan demo fiksyen?`
5. Show the Malay draft and citation.
6. Send `I need a human` (or a sensitive fictional payment/refund question).
   Show the high-priority handoff ticket and activity instead of a draft.
7. Explain that low-confidence questions also hand off rather than guessing.

## Close — 1 minute

State the current boundary clearly: this is a private, fictional-data demo;
live Meta intake and every outbound WhatsApp reply remain disabled. Next,
client-approved knowledge, ownership, retention wording, and live-message
behaviour must be agreed before production activation.
